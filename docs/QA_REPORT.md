## P0 — 壞掉

### P0-1　Jackpot 期望值超過押注：實際 RTP 約 280%
- **重現**：`node --experimental-strip-types tools/sim.ts 200000` 得 RTP 96.7%，但模擬**沒有算 Jackpot**。用 `Main.ts` 的數值計算：每轉 Jackpot 期望回饋 = Σ(獎金 × bet/8 ÷ 機率) = **1.838 倍押注**。光 MINI 一項（機率 1/800，派彩 823.6 倍押注）就是每轉 1.03 倍押注。總 RTP ≈ 96.7% + 183.8% ≈ **280%**。
- GRAND 派彩 18,502 倍押注，也超過遊戲說明寫的「最高贏分 5000 倍」。
- **原因**：`Main.ts:25` `JP_ODDS = [120000, 25000, 4000, 800]`、`Main.ts:66` `jpVals`、`Main.ts:673-676` `maybeJackpot()` 以 `jpVals[i] * bet / 8` 派彩。
- **修法**：先決定 Jackpot 要占多少 RTP（例如 1~2%），再反推機率。例如 MINI 823.6 倍押注要占 0.5% RTP，機率需約 1/165,000。另一種做法是改成固定倍數（MINI 20×、MINOR 50×、MAJOR 500×、GRAND 2000×）並把 Jackpot 抽成從主遊戲 RTP 扣掉。修完後把 Jackpot 加進 `tools/sim.ts` 一起模擬。

### P0-2　購買確認窗開著時按空白鍵：扣 880 卻拿不到免費遊戲
- **重現**（建置版 8765，購買鈕仍可見）：點「購買特色」→ 確認窗出現 → 按 **Space**（一般旋轉開始，扣 8）→ 點「購買」→ 點數再扣 880（20000 → 19112），但模式仍是 base、沒有進免費遊戲。
- **截圖**：`buy_space_then_confirm_lost_880.png`（實測數據：`{"busy":true,"bal":19992}` → 點購買後 `{"bal":19112,"mode":"base"}`）
- **原因**：`Main.ts:340-350` `buyFeature()` 在確認窗開著時沒有把 `busy` 設成 true，鍵盤事件（`Main.ts:306-308`）也不會被遮罩的 `BlockInputEvents` 擋住。按「購買」後先扣錢（`balance -= cost`），再呼叫 `playBaseSpin(true)`，結果 `playBaseSpin` 因為 `busy` 直接 return。
- **修法**：開窗前設 `this.busy = true`，取消時還原；或在 `onKey` 裡檢查「有任何彈窗開著」就忽略 Space；扣錢移到 `playBaseSpin` 確定會執行之後。說明視窗（`showInfo`）開著時按 Space 也會在不透明面板底下旋轉，同一個修法一起處理。
- 備註：原始碼已 `BUY_ENABLED = false`，但建置版還是開著；重新開啟購買功能前一定要先修。

### P0-3　全螢幕遮罩與閃光無法半透明：大獎、開場、Jackpot、說明的背景全黑，轉場出現整片實心橘／紫色塊
- **重現**：任何遮罩演出。取樣像素：大獎、免費遊戲開場、Jackpot、說明視窗背景全畫面都是 `(5,1,12)`，盤面和角色完全看不到。觸發 `fire` 轉場第 0.7 秒時，全畫面是**實心** `(255,179,71)` 橘色方塊。
- **截圖**：`wave_flash_solid_orange.png`、`pc_fgintro_opaque_black.png`、`pc_bigwin_0p7s_already_mega.png`；對照原作半透明壓暗：`ref_530s_superwin_dimmed.png`
- **原因**：遮罩與閃光都是 `Graphics` 畫的（`Celebrations.ts:23-36` dim、`:177` 轉場閃光、`:296` 覺醒白閃、主工作階段新加的 `:139` bigWinIntro 白閃、`Kit.ts:169` `Kit.panel`），再用 `UIOpacity` 淡入淡出。實測只有 0 會隱藏，0 以外的透明度都當成全不透明（Graphics 的頂點色不吃節點透明度）。所以：
  - 遮罩一出現就全黑（原作是壓暗後還看得到盤面）；
  - 淡出 `undim()` 沒有漸變，會直接消失；
  - 轉場閃光變成 0.7 秒的實心色塊；
  - 確認窗、說明、結算面板淡出時，文字會漸隱，面板本身卻是瞬間消失。
- **修法**：遮罩與閃光改用 `Sprite`（用現成的白色貼圖，例如 `fx/soft.png`、`dot.png`，或 1×1 白圖，`sizeMode=CUSTOM` 加 `color` 染色）。Sprite 會吃 `UIOpacity`。面板若要保留圓角，可改成 9-slice 圖，或在 tween 的 `onUpdate` 裡用帶 alpha 的 `fillColor` 重畫。

## P1 — 明顯瑕疵

### 🔤 P1-1　所有點陣數字都偏低約 2 成字高、底部描邊被切掉（根本原因）
- **影響**：標題列贏分數字下半被盤框金邊蓋住、倍數框「37x」偏低、免費遊戲開場「15」壓到文字、大獎數字、盤面贏分標籤。
- **截圖**：`pc_header_number_clipped.png`（「9.20」下半壓在牌匾下框上）、`fg_multring_text_overflow.png`
- **原因**：`tools/make_bmfont.py:28,30` 畫字時 y 只用 `STROKE + 2`，沒有扣掉字型的上方留白 `bbox[1]`。實測 `num_gold.png` 每格 120px 高，數字「0」實際筆畫在 y=38~120，上方空 38px，下緣剛好貼到格子底（描邊被切）。Cocos 依整格垂直置中，所以每個數字都往下偏。
- **修法**：`glyph()` 改成 `text((STROKE+3-bbox[0], STROKE+2-bbox[1]))`；格高改成 `bbox[3]-bbox[1]+STROKE*2+6`（所有字取最大值統一）；`base` 依此重算。重新產生後，P1-2、P1-3、P1-5、P1-6 的位置都要重新微調一次。

### P1-15　倍數球在施法打中前整格隱藏，盤面出現空洞

### P1-16　轉場火焰／紫焰貼圖四邊沒有羽化，硬邊清楚可見
- **截圖**：`wave_fire_hard_edges.png`（左側和中間各有一條垂直硬邊，上方有一條水平硬邊）
- **原因**：`fx_fire_wave`、`fx_purple_wave` 貼圖邊緣不透明，`Celebrations.ts:162` 起的 `wave()` 把 3 層 1.6 倍畫面寬的貼圖平移、旋轉 ±6°，矩形邊界就露出來。
- **修法**：在 `tools/process_art.py` 或 `make_fx.py` 對這兩張圖的四邊做 15~20% 的 alpha 漸層；或改成原作那種「火焰龍捲」單張大圖（`ref_09s_fg_trigger_sequence.png` 第 8~10 格）。

### P1-17　覺醒特寫的閃電有多邊形硬邊
- **截圖**：`pc_awaken_lightning_hard_edges.png`（左下閃電被斜直線切斷，頭上也有直線切口）
- **原因**：`seth_awaken` 的 `bolt_l／bolt_r／bolt_c` 附件，以及 `Celebrations.ts:261` 起 `awaken()` 隨機生成的 `fx_lightning` 貼圖，邊緣都沒有完全透明（或 atlas 區塊太貼）。
- **修法**：閃電貼圖外圍加 8~12px 全透明邊並羽化；atlas 加 padding 2px 以上。

### P1-18　購買免費遊戲 RTP 108%（玩家穩賺）
- **重現**：`tools/sim.ts` 輸出 `buyRTP=108.0%`（免費遊戲平均 122.7 倍押注，售價 110 倍）。
- **原因**：`SlotEngine.ts:97` `BUY_COST_X = 110`。
- **修法**：要對齊約 96% RTP 的話，售價改成約 127 倍（122.7 ÷ 0.965）；或保持 110 倍、調低購買版免費遊戲的倍數球權重。目前購買功能在原始碼是關閉的，重新開啟前必須修。

### P1-19　Jackpot 條顯示的金額和實際派彩不一致
- **重現**：押注改成 0.4 時，Jackpot 條仍顯示 MINI 6,589，但中獎只會派 329（`jpVals × bet/8`）；押注 8 時，派彩用的是固定初值 7,702.37，條上顯示的是不斷累加的 7,703.x；中獎後條上的數字也不會歸零。
- **原因**：條上的數字在 `Hud.ts:56,87` 自己累加；派彩用 `Main.ts:66,676` 另一組固定值。
- **修法**：Jackpot 數值只放在 Main 一處，條上顯示 `值 × bet/8`（或固定顯示派彩金額），中獎後歸零到種子值。必須和 P0-1 一起處理。
